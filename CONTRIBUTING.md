# Contributing

Thank you for helping improve Daily Business Agent.

## Before contributing

- Use synthetic data only.
- Do not submit credentials, tokens, certificates, private keys, customer data, store data, production addresses, internal repository references, or private deployment configuration.
- Keep changes focused and explain their user impact.
- Do not include generated installers, build output, runtime state, or local reports in commits.

## Development workflow

1. Create a branch from `main`.
2. Make one focused change.
3. Add or update tests where applicable.
4. Run the relevant checks locally.
5. Open a pull request describing what changed, why it changed, and how it was validated.

## Pull request expectations

A pull request should include:

- a clear summary;
- the reason for the change;
- security or privacy impact, when applicable;
- validation steps and results;
- screenshots only when user-interface behavior changed, with all sensitive information removed.
